## 更新内容

v1.0.1 是向后兼容的性能维护版本，重点改善大图、小图交替识别后的耗时。

- REC 执行计划从全局共享 32 条 LRU 改为默认 8 个槽位各自最多 16 条的有界缓存，减少不同尺寸互相淘汰。
- 上传或 CTC 缓冲区变化时，只失效受影响槽位；共享工作区变化时仍完整失效，缩减槽位时先清理旧命令引用。
- 增加缓存策略、宽度切换、缓冲区恢复和混合尺寸回归测试，保留正确性与资源预算检查。
- 更新中英文文档，说明性能数据、内存取舍及 GPU 空闲状态对间隔调用耗时的影响。

不修改 C ABI v1、HTTP API v1、配置和日志 Schema v1；不修改模型、FP32 精度、DET960 或结果排序。

## 本机性能对比

Windows 10、RTX 4060 Laptop GPU，同一句柄预热后交替识别 500×500 和 2448×3264 图片，30 轮测试的流水线中位数：

| 模型 | 小图：优化前 → 后 | 大图：优化前 → 后 |
| --- | ---: | ---: |
| Tiny | 32.21 → 20.05 ms | 151.47 → 86.44 ms |
| Small | 60.91 → 38.69 ms | 269.17 → 158.80 ms |
| Medium | 115.33 → 91.14 ms | 464.08 → 351.14 ms |

对比测试中，文字、坐标、置信度与分类结果一致。缓存增加有内存代价；上述数据来自版本号更新前的本机优化构建，不是所有设备的性能承诺，也不代替最终发布包验收。
详细报告：[REC 混合尺寸缓存优化](https://github.com/lxw112190/lw.PPOCR.Vulkan/blob/v1.0.1/docs/REC-CACHE-SIZE-SWITCH.md)。

## 下载与使用

- Windows x64：`lw.PPOCR.Vulkan-v1.0.1-windows-x64-full-ocr.zip`
- Linux x64：`lw.PPOCR.Vulkan-v1.0.1-linux-x64-full-ocr.tar.gz`
- 每个归档附同名 `.sha256` 校验文件。

部署包包含模型、字典、HTTP/Web、配置、服务脚本、示例与测试图片；Windows 包另含 C# WinForms Demo。
目标机仍需兼容 Vulkan 1.1 的设备、Loader 和显卡驱动；没有兼容设备时不自动回退 CPU OCR。

升级建议：停止 Demo/HTTP 服务，备份原配置，将新版本解压到独立目录，迁移自己的配置及 API Key，验证后切换服务路径。保留旧目录便于回滚，不覆盖正在运行的 DLL。

## 已知限制

GPU 空闲后会进入省电状态，间隔几秒调用的延迟可能高于连续预热调用。本版优化的是混合尺寸缓存，并未消除驱动电源状态切换的影响，也不会默认后台持续推理来维持高频。
首次或新尺寸调用仍可能需要准备计划；缓存是有界的，工作集超过容量时仍会淘汰。Linux 软件 Vulkan CI 不等同于 Linux 实体 GPU 验收。

## English summary

Backward-compatible maintenance release improving REC plan reuse across mixed image sizes. The default path uses bounded per-slot LRU caches and selective invalidation. Models, FP32 precision, DET960, result ordering and all v1 public contracts remain unchanged.

Local warmed mixed-size benchmarks show lower latency, with additional cache memory cost. These measurements precede the version bump and are not universal performance guarantees or final-archive qualification. GPU idle-power transitions can still increase spaced-request latency.

Download the Windows x64 ZIP or Linux x64 tar.gz and matching SHA-256 file. Stop services before upgrading, extract into a separate directory, migrate configuration/API keys and validate before switching over. Compatible Vulkan hardware, loader and vendor drivers remain required; no automatic CPU OCR fallback is provided.
