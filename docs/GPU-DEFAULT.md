# GPU 前处理与共享原图：默认策略

2026-10-02 / `0.5.0-dev.2` / `gpu-default1`。

此前已验证的 GPU 缩放、归一化、透视裁剪、竖长区域旋转和共享原图，现已接入原生默认路径，而不是只由 Demo 脚本开启。C ABI、C#、Python、HTTP 和直接运行 EXE 都使用相同策略；网络继续 FP32，DET 长边仍为 960。

## 自动选择与手动控制

三个环境变量：`LWVK_GPU_DET_PREPROCESS`、`LWVK_GPU_TEXT_PREPROCESS`、`LWVK_GPU_CROP_PREPROCESS`。

| 值 | 行为 |
| --- | --- |
| 未设置、空值或 `auto`（默认） | 所选 GPU 支持 `shaderFloat64` 且未开启 GPU profiling 时自动启用；否则保留 CPU 图像处理 |
| `0` | 显式关闭对应处理；网络仍在 Vulkan GPU 上执行 |
| `1` | 强制启用；缺少 `shaderFloat64` 或与 GPU profiling 冲突时明确拒绝 |

GPU 裁剪需要 DET 和文字行 GPU 前处理同时启用。裁剪为 `auto` 时会随前两项关闭；裁剪强制 `1` 而前两项任一为 `0` 时拒绝初始化。其他值拒绝，避免拼写错误被静默忽略。必须在新进程加载 DLL 前设置；修改环境后应关闭并重新启动程序。

普通 Demo 启动脚本将三个变量设置为 `auto`，清除诊断模式的影响。直接运行 EXE 或 HTTP 会继承父进程环境。兼容/性能对照使用 `Start-CSharp-Demo-CPU-Preprocess.bat`（三项 `0`）；原有实验脚本保留用于指定局部路径，GPU-Crop 脚本明确要求三项 `1`。

`LWVK_GPU_PROFILE=1` 的自动模式保留 CPU 前处理，因为当前时间戳诊断只支持该路径。它不是生产性能档。自动选择只发生在初始化时，不会在推理失败、超时或设备丢失后切换路径。没有可用 Vulkan 设备仍明确报错，**不是 CPU 推理回退**。

## 默认流水线（支持 shaderFloat64 的设备）

```text
CPU：解码/相机 BGR 输入与尺寸规划
  → GPU：原图一次上传，DET 缩放/归一化与检测网络
  → CPU：DB、框扩展、排序、透视系数
  → GPU：BGR8 透视裁剪、竖长转横向、可选 CLS 前处理/网络
  → CPU：方向判断；GPU：REC 180° 采样/缩放/补边/归一化/网络/贪心标签
  → CPU：CTC、字典、UTF-8、JSON → C ABI / C# / Python / HTTP
```

裁剪与网络缩放保持两个 GPU 步骤，保留原插值和 BGR8 中间舍入语义，不以降低精度换速度。插值使用 FP64；这不意味着模型网络改为 FP64。仅识别接口直接使用文字行 GPU 前处理，不执行 DET/CLS 或共享原图裁剪。

同句柄仍串行；三图共享 context/device，不是三网络并行。源图/暂存/裁剪/元数据按保守合计从每图工作区预算中扣除；低预算拒绝后可恢复较小请求。最多 8 行有界提交；不是分配八份网络激活。

“其他耗时”包含 GPU 裁剪准备、提交与等待，以及 CPU 后处理；不能理解为纯 CPU 时间。原图上传计入 DET。工作区上限不是整个进程或 VRAM 上限，权重和驱动额外占用内存。

## 验证与性能依据

优化本身的对拍、100 图性能和局限保留在 [历史 GPU 裁剪实验报告](GPU-CROP-EXPERIMENT.md)。其中默认关闭的叙述指实验发布时的行为，不再是当前默认。

本轮另行验证未设置变量的默认路径、显式 `auto`、全 GPU `1`、CPU 前处理 `0` 及部分关闭，CLS 开/关和独立句柄的预测逐项一致；能力不足与 profiling 的选择通过 108 组合纯策略单元测试覆盖。无 `shaderFloat64` 的真实显卡尚未实测，不能把策略测试说成硬件兼容认证。

本机测试不替代 Linux CI、更广驱动验证或长期内存泄漏测试。历史性能不是对所有设备、所有冷启动换图的保证，也不是本轮重新比较 DML 的结果。

本轮默认路径的原始报告、两卡验证范围与旧/新默认性能口径见 [gpu-default 验证索引](reports/gpu-default/README.md)。完整 C# 体验包 revision 为 `gpu-default1`，版本号保持 `0.5.0-dev.2`；不覆盖之前的实验包。
